# OctoAcme Project Management Docs

This directory contains OctoAcme's project management guidance for cross-functional projects, from initial validation through delivery and continuous improvement. Use the process documents below as a shared reference for onboarding and day-to-day project work.

## Process summary

OctoAcme manages projects through a lifecycle of initiation, planning, execution, release, and retrospective improvement. Teams establish customer and business outcomes, align stakeholders and resources, and move approved work into a prioritized, estimated backlog with acceptance criteria, milestones, a Definition of Done, and documented risks and dependencies.

During execution, teams track work on a project board, use regular delivery check-ins to surface progress and blockers, and escalate issues through the PM, Product Lead, and sponsor as appropriate. Project Managers coordinate delivery, schedules, risks, and communications; Product Managers own outcomes and prioritization; developers build and test the work; QA validates acceptance; and stakeholders contribute input and decisions.

Quality is integrated throughout delivery: teams use unit tests, integration tests where applicable, end-to-end smoke tests for critical flows, automated CI testing and linting, security scanning, and review approvals. Releases require acceptance criteria to be met, release notes and rollback plans to be prepared, staging smoke tests, production verification, and stakeholder communication. Retrospectives after sprints, releases, milestones, or incidents turn learnings into owned, measurable improvement actions.
